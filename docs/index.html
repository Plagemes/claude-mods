    Under the hood

    Events in. Your rules out.

    A mod is a plugin of function hooks. Claude Code emits events: a tool call, a prompt, a finished turn, a frame to draw. Your hook sees each one and can let it pass, rewrite it, answer it, or draw something new.

    Claude Code emits

    • tool.callBash, Edit, Write, Read…
    • prompt.submitwhat you just typed
    • turn.completethe turn is done
    • ui.rendera frame to draw
    • session.starta new session

    Your mod hooks in

    ($, e, next) => …
    • Guard deny with a reason
    • Rewrite next({ ...e })
    • Observe count, time, log
    • Render draw into the UI

    You see

    • A denial with a safer path
    • A status line or band
    • A live pane
    • A new slash command
    • A toast or a sound

    Mods run in a sandbox with no DOM and no Node. Everything outside reaches them through $, the engine interface, so a mod can only do what its hooks ask for.

    Build a mod

    Your idea is one file away.

    If you can write a function, you can write a mod. Start from the example, load it live, and open a pull request when it feels right.

    1. Create mods/<name>/ with a plugin.json and a hooks module.
    2. Load it live with claude --plugin-dir mods/<name>.
    3. Check it with claude plugin validate mods/<name>.
    4. Add it to catalog.json, run node scripts/build.mjs, open a PR.
    Read the contributing guide Request a mod
    hooks/register.tsplugin.json 
    import type { Register } from 'claude-code'

// Block force-pushes to main, explain the safer path.
export const register: Register = on => {
  on('tool.call', { tool: 'Bash' }, ($, e, next) =>
    /git push .*--force\b.*\bmain\b/.test(e.command)
      ? { deny: 'Use --force-with-lease, never on main.' }
      : next(e),
  )
}
